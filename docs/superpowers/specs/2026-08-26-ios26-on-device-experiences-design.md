# iOS 26 设备端体验设计

## 目标

将现有的单页 `AppleOnDeviceModelDemo` 改造为原生 SwiftUI 体验库，让用户每次发现并亲自体验一项 Apple 端侧能力。应用仅演示 iOS 26 公开 API，不包含基准测试、聚合评分、批量执行、云端回退或模拟模型输出。

## 产品定位

该产品是一个交互式功能库，而不是诊断仪表板。其核心承诺是：选择一种体验，提供输入，运行真正的公共 API，并检查当前设备上的结果和限制。

所选的视觉方向是2026年8月26日批准的轻型“设备上体验”概念：

- 暖灰白色基面；
- 大号黑色编辑风格标题；
- 柔和的珊瑚色、绿色、蓝色和紫色分类强调色；
- 可水平滑动的精选功能区；
- 具有图像主导条目的分组功能部分；
- 简短、诚实的设备要求标签；
- 宽敞的间距和原生 iOS 排版。

该设计稿只是视觉目标，不是技术事实来源。实际实现应根据当前 iOS 26.5 SDK 校正能力分组和可用性标签。

## 范围

该应用程序面向 iOS 26 和已安装的 Xcode 26.6 / iOS 26.5 SDK。它仅包含可用于 iOS 26 版本的公共 API。

### 语言和文本

1. 基础模型 — 通过 `SystemLanguageModel.default` 和 `LanguageModelSession` 进行自由形式的提示和响应。
2. 引导生成 — 使用 `@Generable` 和 `@Guide` 的结构化 Swift 输出。
3. 内容标记 — 使用 `SystemLanguageModel(useCase: .contentTagging)` 的主题、实体、动作和情感。
4. 流式生成——将 Foundation Models 的增量输出作为独立体验。
5. 工具调用——一种附加到 `LanguageModelSession` 的本地确定性演示工具；没有网络访问或数据库。
6. 翻译 — 通过翻译框架和系统语言资产进行文本翻译。
7. 自然语言——通过 NaturalLanguage 进行语言识别、标记化、命名实体和情感。

### 相机和视觉

8. 视觉 — 一页具有可选的公共视觉模式：OCR、条形码识别、人体姿势和图像分类（由 SDK 支持）。每种模式仅处理选定的图像并报告其自己的结果。

### 语音和声音

9. 语音转录 - 使用 `AVAudioEngine` 捕获麦克风音频，使用 `SpeechAnalyzer` 和 `SpeechTranscriber` 进行分析，并具有实时转录和停止/最终行为。
10. 声音识别——麦克风或通过声音分析分析选定的音频并进行排名分类。

### 创建和系统

11. 图像创建器 — 通过 `ImageCreator` 提示驱动的图像创建（如果可用）。
12. Image Playground — 启动并完成系统提供的图像生成体验。
13. 书写工具 — 可编辑文本字段以及调用系统书写工具 UI 的说明。
14. Genmoji — 文本输入集成和调用系统体验的说明；不尝试访问其内部模型。
15. 智能回复 - 仅演示已安装的 SDK 公开的公共对话上下文或键盘集成。如果没有独立的可调用 UI 可用，该页面会解释支持的集成边界，并且不会生成响应。
16. 应用程序意图 - 显示相反方向的无害示例应用程序意图，系统可以在其中调用应用程序功能。此页面不要求访问 Siri 的内部模型。
17. 自定义适配器 - 检查并解释 iOS 26 适配器路线。仅当存在兼容的 `.fmadapter` 和所需的权利时才启用加载；否则该页面仍然是诚实的设置指南。

## 明确排除

- iOS 27 API、AFM 3 变体、图像附件、动态配置文件和统一的 `LanguageModel` 后端。
- 基准、排行榜、准备分数、通过计数或“运行所有”操作。
- 云 API、私有云计算后备、第三方模型、Core ML 自定义模型和 MLX。
- 模型权重、私有框架、私有 Siri 上下文或声称测试了无法访问的内部模型。
- 数据库、帐户系统、分析、持久性和不相关的设置。

## 信息架构

### 首页

主屏幕仅聚合发现。它从不调用模型。

- 标题：“设备上体验”和“选择一些尝试。”
- 特色架子：三个可滑动、单一功能的入口点。初始设置：语音转录、内容标记和图像创建器。
- 类别部分：语言和文本、相机和视觉、语音和声音、创建和系统。
- 每个部分都显示一个小的精选子集以及“查看全部”。
- 每个项目都包含标题、代表性视觉效果和一个简洁的状态，例如“在此设备上就绪”、“需要 Apple Intelligence”、“需要资产”或“系统 UI”。
- 选择一项将导航至一个体验页面。

`Content Tagging` 属于语言和文本。翻译可用性取决于翻译语言资产，而不是 Apple Intelligence。

### 类别页面

每个类别页面都提供了轻量级的编辑概述及其个人体验的完整列表。它不执行模型或重复结果 UI。

### 体验页面模板

每个体验页面包含：

1. 英雄区域包含功能名称、简短描述、框架、最低操作系统和当前设备状态。
2. “它的作用”解释与现实的用例和限制。
3. 特定于功能的输入表面。
4. 仅运行此功能的一个主要操作。
5. 防止重复执行的加载/进度状态。
6. 结果表面包含实际的公共 API 输出、经过的时间以及适当的复制/选择支持。
7. 内嵌错误或不可用的解释。
8. “如何使用它”部分包含核心公共 API 名称和简洁的步骤。
9. 隐私说明，说明处理是在设备上进行还是委托给系统 UI。

## 专用交互模式

### 文字体验

使用多行文本编辑器、示例输入芯片、清晰的操作、一个主要运行按钮和可读的结果块。引导生成和内容标记呈现标记的结构化字段而不是原始 JSON。

### 语音

使用大型录音/停止控件、实时录音状态、转录表面、语言/资产状态、语音运行时间和明确的最终确定。保留现有的工作 `SpeechAnalyzer`、`SpeechTranscriber` 和动态音频格式处理。

### 视觉

仅当选定的视觉请求返回几何体时，才使用照片选择或相机输入、模式选择器、图像预览、一项分析操作和视觉结果叠加。图像下方的文本结果仍然可供选择。

### 声音分析

自信地使用录音/停止或文件选择、简短的分析窗口和排名声音标签。它不得暗示语音转录。

### 图像创作

使用提示编辑器、仅在通过公共 API 公开时的样式选择、生成进度、生成的图像预览以及系统提供的保存/共享行为。 Image Playground 仍然是一种系统表体验。

### 系统集成

编写工具、Genmoji、智能回复和应用程序意图解释并公开实际的系统入口点。如果体验要求用户调用系统菜单、键盘、Siri 或工作表，则页面会引导该操作，而不是呈现虚假的应用程序拥有的“运行”按钮。

### 适配器

适配器页面将文档与执行区分开来。它仅检测本地可用的资产和与权利兼容的加载。没有添加捆绑的假适配器或下载服务器。

## 可用性模型

每个体验都将其特定于框架的状态映射到共享的表示模型：

- 准备好
- 需要苹果情报
- Apple 智能已禁用
- 模型未准备好
- 所需资产
- 需要许可
- 设备不符合条件
- 仅系统用户界面
- 需要设置
- 不支持

底层服务保留了原有的Framework原因。 UI 永远不会将“设备不合格”转换为一般成功或启用无法运行的操作。不可用的页面仍然可以导航，以便用户可以阅读要求和实际原因。

## 架构

### 表现层

- `ExperienceCatalog` 定义不可变的元数据、类别、排序、要求和视觉标记。
- `HomeView`、`CategoryView` 和可重用图库组件呈现导航。
- 每个功能都有一个专注的 SwiftUI 体验视图和视图模型。
- 共享组件涵盖状态徽章、介绍部分、输入/结果界面、延迟、错误和使用说明。

### 服务

框架调用保留在 SwiftUI 视图之外：

- 用于通用生成、引导生成、内容标记、流式生成和本地工具的 Foundation Models 服务。
- 现有的 `SpeechInputService`，在不替换 iOS 26 语音 API 的情况下进行了改进。
- 专注于视觉、自然语言、翻译、声音分析、图像创建器和功能可用性的服务。
- 系统集成页面仅在必须提供公共表或控制器的情况下使用小型协调器。

服务公开窄协议，因此可以在不调用硬件或模型资产的情况下对视图模型行为和状态映射进行单元测试。

### 导航

使用 `NavigationStack` 和强类型路由承载分类与体验页面。深度链接和状态持久化不在范围内。

## 视觉系统

- 背景：暖灰白色，选择性使用白色内容表面。
- 主要文本：近乎黑色；辅助文本：中性灰色。
- 语言和文本：珊瑚色/橙色。
- 相机和视觉：叶绿色。
- 语音和声音：苹果蓝。
- 创建和系统：紫罗兰。
- 角点：中等、连续的 iOS 半径；避免嵌套圆形容器。
- 阴影：微妙且仅限于交互式特色图块和图像主导的条目。
- 版式：带有粗体编辑标题的原生动态字体样式。
- 图标：用于控制和状态的 SF 符号；为图像主导的画廊条目生成或由源支持的缩略图。
- 辅助功能：动态类型、足够的对比度、VoiceOver 标签、非彩色状态文本、44 点最小目标和简化运动兼容过渡。

## 错误处理

- 仅当相应体验开始时才会请求权限。
- 拒绝的权限显示可恢复的说明和设置指南。
- 缺少的资产仅在官方框架提供时才显示准备或下载操作。
- 模型和框架错误会内联显示，而不会崩溃或导航离开。
- 取消被视为正常状态。
- 每个操作仅记录实际尝试的延迟。

## 测试策略

### 单元测试

- 目录成员资格、类别放置和路线唯一性。
- 每个服务的可用性状态映射。
- 视图模型输入验证、加载状态、结果映射、延迟、取消和错误处理。
- 结构化生成解码和显示模型。
- 现有的语音记录累积和音频会话排序回归。

### 构建验证

- 针对已安装的 iOS 26.5 模拟器 SDK 进行构建测试。
- 通用 iOS 模拟器构建必须以 `BUILD SUCCEEDED` 结尾。
- 模拟器会验证导航和 UI 状态，但并不是 Apple Intelligence 模型运行的证据。

### 手动设备验证

- 导航每个主页和类别条目。
- 运行连接设备支持的所有功能。
- 验证不可用和权限被拒绝的状态。
- 验证每个体验页面仅运行一项功能。
- 确认没有发生网络或云回退。
- 捕获每个手动测试的结果、延迟、设备型号、操作系统版本和可用性原因。

## 完成标准

- 每个范围内的 iOS 26 功能都有一个可发现的单独页面。
- 主页和类别页面可以导航，但从不执行功能。
- 每个可执行页面都使用其真正的公共框架 API。
- 系统 UI 和仅设置功能都被诚实地标记。
- 所选画廊视觉方向在实现的 UI 中是可识别的。
- 不存在基准、总分、批量运行、伪造输出或云回退。
- 单元测试和通用模拟器构建成功。
- 真正的模型执行仅针对在合格硬件上手动观察到的功能。
