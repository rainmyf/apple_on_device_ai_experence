# Batch image sharing

User scope: expose 发送到我的华为手机 in Photos share-sheet through same AppShortcuts registration as apple_ai, and a configured image-accepting Share Sheet shortcut. Default image input becomes a batch. Preserve image title, background LongRunningIntent, message demo and its independent wire.

Wire v2 for image service `_imgbridge._tcp`, port22856: one TCP connection per batch. First header ASCII `IBAT` plus uint32 LE image count (1..20). For each image: uint32 LE JPEG byte length (1..20MiB) then JPEG. Total JPEG bytes <=100MiB. After EACH image receiver replies one byte: 0=durably saved (last image: saved and preview API accepted), 1=reject/save/decode failure, 2=all files saved but final preview launch failed. Sender waits each ACK before transmitting next image. On error close connection, report partial count accurately; no silent resends. 30s idle/per-image operations, final iOS image operation45s with Harmony preview capped10s, discovery350ms/5s unchanged. This coordinated protocol replaces old image-only frame. Message service stays unchanged.

iOS: @Parameter key image changes to [IntentFile] with .image supported types, keep title, explicit input connection. PhotosPicker ordered multi-selection up to20. Load/normalize/send sequentially <=2048 JPEG to bound memory; do not load all source photos at once. LongRunningIntent wraps batch transfer, progress per images/actual bytes and cancellation cleanup. AppShortcutsProvider with AppShortcut mirrors apple_ai; registration is distinct from the user's Share Sheet setting. Root/list structure stays.

Harmony: streaming parser with bounded image buffer, decode/validate and persist each image under context.filesDir/received-images/<unique-batch-dir>/<index>.jpg; close file before ACK. Finish batch invokes public system preview API for LAST file only. User permits app-private persistence; do not claim saved to public gallery if only sandbox files exist. Prefer actual Gallery image viewer if public supported invocation exists; if only PreviewKit official API available, label exactly system file preview rather than claim Gallery integration. Persist paths/history enough to reopen last file via button after failure/relaunch; no broad photo library permission just for storage. File URI and read grant if external viewer. Do not invoke preview per image. ACK2 when final preview fails, files retained.

Validation: streaming fragmentation/count/length/total bounds, partial failure, sequential ACK, no premature preview; native builds; independent real devices install when connected. Current HDC empty/iPhone paired possibly locked; do not call physical success without actual run. User requested current changes alongside previously unverified message install; include latest two demos in final builds.
